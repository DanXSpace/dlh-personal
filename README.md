# Daniel Lee Holung — personal site

A static Astro site: portfolio, writing and personal identity. Product, design and
architecture decisions live in [`docs/`](docs/) (`prd.md`, `design-spec.md`,
`architecture.md`, and decision records in `docs/adr/`).

## Requirements

- Node.js 24 LTS (minimum 22.23.4, required by Astro 7). `.nvmrc` pins it: run `nvm use`.
- npm 10 or newer.

## Setup

```sh
nvm use
npm ci
npx playwright install chromium   # browser for the end-to-end and accessibility tests
```

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Start the dev server at `http://localhost:4321`. |
| `npm run build` | Build the static site into `dist/`. |
| `npm run preview` | Serve the built `dist/` locally. |
| `npm run check` | Type-check `.astro` and `.ts` files with `astro check` (strictest tsconfig). |
| `npm run test:unit` | Run unit tests in `tests/unit/` with Node's built-in test runner. |
| `npm run test:e2e` | Run Playwright browser and axe accessibility tests against the built site. Run `npm run build` first. |
| `npm run verify` | Run the type check, unit tests, build and browser tests in that order. Exits non-zero if any step fails. |

Run `npm run verify` before every commit.

## Tests

- `tests/unit/`: pure functions in `src/lib/`, run directly by Node (native TypeScript type stripping, no test framework).
- `tests/e2e/`: Playwright against `astro preview` of the production build, including responsive overflow checks.
- `tests/a11y/`: axe-core checks against WCAG 2.2 AA rules.

### Fixture content

Template tests will use fixture entries in `tests/fixtures/content/`, which never ship.
`CONTENT_SOURCE=fixtures npm run build` writes to `dist-fixtures/` instead of `dist/`.
Content collections don't exist yet. When they're added, their loaders read from the
fixtures directory in that mode. The production build reads only `src/content/` and
writes `dist/`. See [ADR-0004](docs/adr/0004-fixture-content-via-separate-build.md).

## Environment variables

All are read at build time. None are secrets, and none belong in the repository's `.env` files.

| Variable | Values | Effect |
| --- | --- | --- |
| `PUBLIC_SITE_ENV` | `production`, or anything else / unset | Only `production` makes the site indexable. Any other value, including unset (the default), adds `<meta name="robots" content="noindex, nofollow">` to every page and builds a disallow-all `robots.txt`. Set it to `production` at the launch gate, not before. |
| `WORKERS_CI_BRANCH` | set by Cloudflare Workers Builds | When present and not `main`, the build is non-indexable regardless of `PUBLIC_SITE_ENV`, so preview URLs never get indexed ([ADR-0005](docs/adr/0005-previews-noindex-by-branch.md)). Don't set it yourself. |
| `CONTENT_SOURCE` | unset, `production`, `fixtures` | `fixtures` builds test fixture content into `dist-fixtures/` (see above). Never set it on a deployment. |

## Deployment

The site deploys to [Cloudflare Workers static assets](docs/adr/0001-cloudflare-workers-static-assets.md):
`dist/` is uploaded as-is, with no Worker script and no Astro adapter.

- **`wrangler.jsonc`** points the Worker's assets at `./dist` and sets
  `not_found_handling: "404-page"`, so unknown URLs serve `404.html` with a 404 status.
  Its `name` must match the Worker's name in Cloudflare (`dlh-personal`), and its empty
  `previews` block is required by `wrangler preview`, the deploy command for non-`main` branches.
- **`public/_headers`** sets security headers on every response (HSTS, `X-Content-Type-Options`,
  `Referrer-Policy`, `Permissions-Policy`, `X-Frame-Options: DENY`) and caches the
  content-hashed files under `/_astro/` for a year as `immutable`.
- **Content Security Policy** is generated by Astro (`security.csp` in `astro.config.ts`) as a
  `<meta>` tag on each page, with hashes for that page's inline scripts and styles. It never
  uses `'unsafe-inline'`. CSP is not applied by `npm run dev`; check it with `build` and `preview`.
- **CI** (`.github/workflows/ci.yml`) runs on every push and pull request: `npm ci`,
  `npm run verify`, and `npm audit --audit-level=high`. It validates but does not deploy.
- **Cloudflare Workers Builds**, connected to the GitHub repository, runs `npm run build`
  then `npx wrangler deploy`. `main` deploys to production, and other branches get preview URLs.
  Workers Builds build variables apply to every branch, so `PUBLIC_SITE_ENV` is set once
  (Settings → Build → Variables and secrets) and previews stay `noindex` through the branch check above.
  Deployment credentials live only in Cloudflare and GitHub settings, never in this repository.

### Run the deployed configuration locally

```sh
npm run build
npx wrangler dev      # serves dist/ with _headers and 404 handling at http://localhost:8787
```
